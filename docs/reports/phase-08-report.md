# گزارش فاز ۰۸ — عملیات تکمیلی منابع انسانی

## الف) خلاصه اجرایی

فاز ۸ **اجرا نشده و مسدود است**. UI و منطق نمونه در Frontend وجود دارند، اما بک‌اند operational برای HR، مدل/سرویس غیبت، قرارداد، چرخه استخدام، import batch، پیوست امن، کامنت، پرونده کارمند، گزارش نقص سازمانی و داشبورد API وجود ندارد.

## ب) فایل‌های تغییرکرده

فایل عملیاتی مختص فاز ۸ در این نوبت تغییر نکرده است. گزارش و وضعیت فاز در اسناد roadmap/report ثبت شده‌اند. فایل حذف‌شده‌ای وجود ندارد.

## ج) دیتابیس

مدل‌هایی نظیر قرارداد، دوره الگوی کاری، غیبت، پیوست، Comment و ImportBatch در migration موجود تعریف نشده‌اند. هیچ Migration جدیدی برای فاز ۸ ساخته نشده است.

## د) API

APIهای HR/Analytics در backend پیاده نشده‌اند؛ به همین دلیل Permission، Organization Scope و نتایج تست قابل ادعا نیستند. endpoint یا گزارش فردی حساس اضافه نشده است.

## هـ) Frontend

صفحات HR، Bradford و نمودار در کد Frontend وجود دارند، اما پیکربندی عادی برنامه Demo API را انتخاب می‌کند و fallbackهای client برای چند endpoint هم وجود دارند. این‌ها اتصال به داده عملیاتی واقعی را ثابت نمی‌کنند. فایل‌های پیوست یا اطلاعات پزشکی عملیاتی در این نوبت ساخته/نمایش داده نشده‌اند.

## و) تست‌ها

- Backend regression suite: ۱۱۰ Passed، ۰ Failed، ۰ Skipped؛ تست مختص فاز ۸ ندارد.
- Frontend suite: ۳۲ Passed، ۰ Failed، ۰ Skipped؛ اعتبار محاسبات واقعی DB/API را اثبات نمی‌کند.
- تست اختصاصی فاز ۸: Passed ۰، Failed ۰، Skipped ۰، Not Run همه.

## ز) موارد باقی‌مانده

- تکمیل احراز هویت، RBAC، Organization Scope و مسیرهای Workflow/ledger موردنیاز.
- تصویب سیاست غیبت، دسترسی پزشکی، retention و پایان همکاری.
- Import امن با preview، گزارش ردیف‌ها و idempotency.
- ذخیره/دانلود کنترل‌شده پیوست و Audit مشاهده/دانلود.
- محاسبه Bradford از سوابق معتبر backend و دسترسی محدود گزارش فردی.

## ح) وضعیت پذیرش

تمام معیارهای پذیرش فاز ۸ **BLOCKED / NOT TESTED** هستند. Bradford در Frontend/Demo به‌تنهایی معیار عملیاتی محسوب نمی‌شود؛ API، داده مبنا و مجوز HR در backend موجود نیستند.
