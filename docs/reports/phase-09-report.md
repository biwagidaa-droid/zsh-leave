# گزارش فاز ۹ — داشبوردها و گزارش‌های مدیریتی

## هدف و وضعیت اولیه

هدف، ارائه تحلیل واقعی و مجاز بر داده Backend است. ممیزی اولیه نشان داد نقشه راه فازهای ۳ تا ۵ تکمیل نشده، API عملیاتی درخواست/دفترکل/گزارش ثبت نشده و نقش‌ها و scope سازمانی عمومی پیاده نشده‌اند. تابع‌های خالص گزارش در `zsh_core` و صفحات گزارش در Frontend وجود دارند، اما جایگزین داده و مجوز سمت سرور نیستند.

## فایل‌ها و قابلیت‌های بررسی‌شده

- بررسی‌شده: `backend/zsh_core/reports.py`، `backend/leave/urls.py`، قرارداد API، `frontend/src/pages/DashboardPage.tsx`، `HrPages.tsx` و `BradfordPage.tsx`، آزمون‌های گزارش و مجوز.
- وضعیت داشبورد کارمند: **PARTIAL** — صفحه و API Client وجود دارد، اما API مانده/درخواست/اعلان عملیاتی در Backend ثبت نشده است.
- وضعیت داشبورد مدیر، HR و هلدینگ: **BLOCKED** — داده، scope و endpointهای معتبر ارائه نشده‌اند.
- گزارش‌های ۱۵گانه، فیلتر سمت Backend، صفحه‌بندی و Export عملیاتی: **NOT IMPLEMENTED**.
- Bradford: **PARTIAL / NOT VERIFIED** — فرمول خالص و UI وجود دارد، ولی endpoint تجمیعی امن، داده غیبت معتبر، الگوی کاری مؤثر تاریخی و سیاست مصوب وجود ندارد؛ در حالت HTTP، خطاهای سرویس‌های مفقود دیگر با داده پیش‌فرض پنهان نمی‌شوند.
- محاسبات سهمیه و دفترکل: **NOT VERIFIED** در جریان گزارش عملیاتی؛ Backend عملیاتی دفترکل وجود ندارد.

## تغییرات این فاز

گزارش‌گیری عملیاتی یا API جدیدی اضافه نشد؛ ساخت چنین API پیش از احراز هویت، scope سازمانی و منبع داده گردش‌کار، ریسک افشای بین‌شرکتی و گزارش نادرست دارد. تغییرات فرانت‌اندِ خطاپوش و سیاست Demo در گزارش فاز ۱۰ ثبت شده‌اند.

## فایل‌ها، API و Migration

- فایل جدید مختص فاز: همین گزارش.
- فایل‌های Backend برای گزارش‌ها تغییر نکردند.
- API جدید/اصلاح‌شده گزارش: هیچ.
- Migration: هیچ.

## آزمون‌ها

- Backend regression: ۱۲۵ موفق، ۰ ناموفق؛ این آزمون‌ها تکمیل API گزارش را اثبات نمی‌کنند.
- Frontend: ۳۴ موفق، ۰ ناموفق؛ تست E2E یا اتصال به داده گزارش واقعی اجرا نشده است.
- آزمون اختصاصی پذیرش گزارش و مجوزهای گزارش: اجرا نشده.

## موانع، محدودیت‌ها و تصمیم‌ها

- پیش‌نیاز مسدودکننده: احراز هویت/RBAC سازمانی، سرویس گردش‌کار، سهمیه و دفترکل واقعی و scope قابل ممیزی.
- PostgreSQL، داده سازمانی و منبع معتبر حضور/غیاب در دسترس نبودند.
- دسترسی HR/مدیران، محرمانگی، سرکوب گروه کوچک و اجازه تحلیل Bradford نیازمند تصمیم سازمانی است.
- موارد تصمیمی در [ثبت تصمیم‌های سازمانی](./phase-09-11-organizational-decisions.md) آمده‌اند.

## وضعیت نهایی فاز

**BLOCKED** — هیچ‌یک از داشبوردها یا گزارش‌های مدیریتی را نمی‌توان بر اساس شواهد فعلی `COMPLETE` اعلام کرد. ادامه پیاده‌سازی بدون حل پیش‌نیازهای فازهای ۳ تا ۵، ایمن یا قابل‌اتکا نیست.
