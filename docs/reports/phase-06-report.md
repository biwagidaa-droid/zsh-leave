# گزارش فاز ۰۶ — تقویم و سیاست‌ها

## الف) خلاصه اجرایی

فاز ۶ **جزئی** پیش رفته است. قابلیت جدید این نوبت، API عمومی و بدون حالت برای تبدیل تاریخ شمسی و میلادی است. منطق موجود شمسی، تعطیلات، سیاست و تخمین روز کاری در `zsh_core` و مدل تعطیلی در Django بررسی شد؛ این اجزا به تقویم عملیاتیِ دارای API و مجوز تبدیل نشده‌اند. تکمیل تقویم سازمانی تا زمان وجود هویت و مجوز سمت سرور ایمن نیست.

## ب) فایل‌های تغییرکرده

- `backend/leave/views.py`: افزودن تبدیل تاریخ با اعتبارسنجی ورودی.
- `backend/leave/urls.py`: ثبت endpoint تبدیل تاریخ.
- `backend/tests/test_api_base.py`: تست مسیرهای معتبر، تاریخ کبیسه شمسی و ورودی نامعتبر.
- `docs/api/api-contract.md`: ثبت قرارداد واقعی API.
- `docs/roadmap/roadmap.md`: ثبت وضعیت واقعی فاز ۶ تا ۸.
- `docs/reports/phase-06-report.md`, `phase-07-report.md`, `phase-08-report.md`, `final-report.md`: گزارش وضعیت و موانع.

فایل حذف‌شده‌ای وجود ندارد.

## ج) دیتابیس

هیچ مدل یا Migration جدیدی لازم نبود. مدل‌های موجود `PublicHoliday` و `PublicHolidayHistory` فقط ثبت دستی محدود را پشتیبانی می‌کنند؛ Work Pattern، نسخه سیاست، دامنه سایت و تاریخچه محاسبات در DB عملیاتی وجود ندارند.

## د) API

| Method | Endpoint | ورودی / خروجی | Permission و Scope | تست |
|---|---|---|---|---|
| GET | `/api/v1/calendar/convert-date/` | `calendar=jalali|gregorian`, `date=...`؛ خروجی تاریخ معادل شمسی و میلادی | `AllowAny`؛ تبدیل ایستا، بدون داده سازمانی | موفق، نوروز، اسفند کبیسه، ورودی نامعتبر |

تاریخ شمسی خارج از محدوده پشتیبانی‌شده به‌جای تبدیل تقریبی با HTTP 400 رد می‌شود.

## هـ) Frontend

در این نوبت صفحه عملیاتی به API متصل نشد؛ Frontend همچنان به‌طور پیش‌فرض از Demo API استفاده می‌کند. API client و کنترل‌های دسترسی backend لازم برای تقویم شخصی/تیمی/سازمانی موجود نیستند. Responsive، Loading، Error و Empty state برای قابلیت جدید **اجرا نشده‌اند**.

## و) تست‌ها

- Backend: ۱۱۰ Passed، ۰ Failed، ۰ Skipped در اجرای کامل `unittest`.
- Frontend: ۳۲ Passed، ۰ Failed، ۰ Skipped؛ build و TypeScript موفق.
- تست متمرکز endpoint: ۵ Passed.
- تست مرورگر واقعی و E2E: اجرا نشده.

## ز) موارد باقی‌مانده

- احراز هویت، RBAC، و فیلتر Organization Scope سمت سرور وجود ندارد؛ APIهای سازمانی نباید پیش از آن فعال شوند.
- Work Pattern و پشتیبانی عملیاتی از شیفت، سایت و قرارداد پاره‌وقت وجود ندارد.
- تعطیلات در DB هستند ولی endpoint مدیریتی، ویرایش تاریخچه‌دار، غیرفعال‌سازی و نمایش تقویم ندارند.
- سیاست‌های موجود در تنظیمات نسخه‌بندی نمی‌شوند و نسخه اعمال‌شده روی درخواست ذخیره نمی‌شود.
- تنظیم واقعی منطقه زمانی، مبدأ سال مرخصی، انتقال و انقضا نیازمند Policy و تصمیم تأییدشده سازمانی است.
