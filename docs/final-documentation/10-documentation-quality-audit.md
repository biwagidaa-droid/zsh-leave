# گزارش ممیزی کیفیت مستندات نهایی ZSH Leave

**تاریخ ممیزی:** ۱ نوامبر ۲۰۲۶  
**دامنه:** هر ۹ سند `docs/final-documentation/01` تا `09`، فایل README همان مجموعه و README ریشه؛ تطبیق ادعاها با کد Backend، Frontend، مهاجرت‌ها، تنظیمات و آزمون‌های موجود. هیچ فایل application تغییر نکرده است.

## خلاصه اجرایی

در نسخه اولیه، چند دستور و ادعای مستندات با مخزن فعلی سازگار نبود: راه‌انداز تنظیمات Django به‌اشتباه ناموجود معرفی شده بود، یک نتیجه‌ی آزمون قدیمی و یک خطای API سهمیه بدون شواهد قابل بازتولید به‌عنوان یافته قطعی درج شده بود، و چند جزئیات workflow، نقش، و اندازه فایل نادرست بود. همه موارد قابل اصلاح در اسناد مربوطه تصحیح شد. README ریشه نیز از توضیح کوتاه و ناسازگار به راهنمای راه‌اندازی، آزمون و محدودیت استقرار تبدیل شد.

## اصلاحات دیگر و کنترل سازگاری

- راهنمای مدیر درباره تقویم تیمی با کد تطبیق داده شد: scope تیم فقط `APPROVED` را نشان می‌دهد؛ scope شخصی وضعیت‌های باز و `WITHDRAWAL_PENDING` را نیز می‌آورد. منبع: [calendar_views.py](../../backend/leave/calendar_views.py).
- جدول نقش/سهمیه دیگر نتیجه API آزموده‌نشده را به مجوز واقعی تعمیم نمی‌دهد؛ دسترسی `admin` به endpointهای سهمیه و فقدان دید او به درخواست فردی جدا نگه داشته شد.
- مسیرهای Frontend در [App.tsx](../../frontend/src/App.tsx)، endpointهای Backend در [urls.py](../../backend/leave/urls.py)، مدل‌ها در [models.py](../../backend/leave/models.py) و شماره مهاجرت‌های `0001` تا `0011` بررسی شدند.
- مستندات آزمون، چک‌لیست تولید و README اکنون بین «کد/سرویس موجود»، «آزمون خودکار»، «آزمون انجام‌نشده» و «آمادگی تولید» تمایز می‌گذارند.

## عدم‌قطعیت‌ها و سناریوهای باقی‌مانده

1. آزمون مستقیم API برای adjustment و import سهمیه در suite فعلی یافت نشد؛ نتیجه موفقیت/شکست runtime از روی وجود کد استنباط نمی‌شود. سناریوی manual در سند ۰۲ باید با داده مصنوعی در DB disposable اجرا و ledger/projection تطبیق داده شود.
2. سه آزمون وابسته به PostgreSQL در اجرای SQLite رد شدند؛ triggerهای پایگاه داده و رقابت هم‌زمانی هنوز در PostgreSQL واقعی تأیید نشده‌اند.
3. استقرار واقعی، TLS/reverse proxy، media persistence، backup و restore، پایش، alerting و پاسخ حادثه از داخل مخزن قابل راستی‌آزمایی نیستند. نمونه فرمان Gunicorn، دستور کامل استقرار production محسوب نمی‌شود.
4. `manager_away` در منطق سرویس/دامنه وجود دارد، اما مسیر API ثبت آن را expose نمی‌کند؛ معلوم نیست این رفتار عمداً فقط داخلی است یا قابلیت محصول ناقص است.
5. معنای حقوقی سال سهمیه، accrual، carry-forward، provisioning/reset کاربر و سیاست نگهداری پیوست‌ها نیازمند تصمیم صاحب محصول/عملیات است.
6. صفحه Executive برای گزارش‌های تجمیعی در UI وجود دارد؛ دسترسی balance برای Executive بدون پروفایل کارمندی کار نمی‌کند. نیاز تجاری این صفحه باید از سیاست مورد انتظار سازمان تأیید شود.

## ارزیابی نهایی کیفیت مستندات

**ارزیابی: مناسب برای مرجع منبع‌محور و بازبینی پذیرش، اما نه گواهی استقرار تولید.** نه سند درخواستی و هر دو README موجود و دارای محتوای substantive هستند؛ لینک‌های داخلی شکسته پیدا نشد؛ دستورهای آزمون منتخب در این محیط اجرا شدند. ادعاهای نادرست/اثبات‌نشده اصلاح و شکاف‌های آزمون/عملیات به‌جای پنهان‌شدن، به‌عنوان عدم‌قطعیت ثبت شدند. تأیید نهایی محصول و آمادگی تولید همچنان منوط به اجرای PostgreSQL، آزمون‌های API باقی‌مانده، UAT و شواهد عملیاتی محیط هدف است.
