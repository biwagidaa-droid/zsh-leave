# راهنمای کارمند

این راهنما قابلیت‌های موجود UI را شرح می‌دهد. جزئیات مجوز سمت سرور نیز در [ماتریس نقش‌ها](08-role-permission-matrix.md) است.

## ورود و صفحه اصلی

۱. در صفحه ورود، نام کاربری و گذرواژه سازمانی را وارد کنید. گذرواژه برای حالت واقعی لازم است؛ انتخاب حساب Demo فقط وقتی Demo در محیط توسعه فعال باشد دیده می‌شود و برای محیط عملیاتی نیست.
۲. سامانه نشست را از `auth/me` بازیابی می‌کند. در صورت نشست منقضی، صفحه ورود نمایش داده می‌شود. پس از کار، از «خروج» استفاده کنید.
۳. داشبورد، اعلان‌ها و پروفایل از منوی اصلی باز می‌شوند. داشبورد، داده‌های شما و اعلان‌های قابل دسترس را نشان می‌دهد؛ محتوا بر حسب نقش/داده تنظیم می‌شود.

## پروفایل و گذرواژه

صفحه «پروفایل» اطلاعات هویتی و سازمانی برگشتی از نشست را نمایش می‌دهد. فرم تغییر رمز، رمز فعلی و جدید می‌گیرد؛ backend اعتبار گذرواژه را بررسی و نشست موجود را حفظ می‌کند. رمز جدید باید حداقل ۱۲ نویسه داشته باشد و با اعتبارسنج‌های Django نیز سازگار باشد. مسیر بازیابی رمز فراموش‌شده در رابط فعلی یافت نشد؛ برای آن با پشتیبان سازمان تماس بگیرید.

## مانده سهمیه

از «مانده سهمیه» سال جاری شمسی را ببینید. مقادیر رابط: کل (پایه + انتقال + اصلاح)، استفاده‌شده، در انتظار، مانده و قابل استفاده. مانده در API از total منهای used محاسبه می‌شود؛ رزرو درخواست باز روی مقدار قابل استفاده اثر می‌گذارد. برای کارمند معمولی انتخاب کارمند دیگر در صفحه دیده نمی‌شود و server نیز باید scope را enforce کند. نبود ردیف سهمیه به معنای «سهمیه صفر تأییدشده» نیست؛ HR را مطلع کنید.

## ثبت و پیگیری درخواست

۱. «ثبت درخواست» را باز کنید و نوع مرخصی فعال و قابل درخواست را انتخاب کنید.
۲. شروع و پایان را با فیلد تاریخ شمسی انتخاب کنید. روز کاری از سرور و policy/work pattern/تعطیلات محاسبه می‌شود؛ تخمین مرورگر، نتیجه نهایی محسوب نمی‌شود.
۳. توضیح را تکمیل کنید اگر نوع انتخابی آن را لازم دارد. جانشین را انتخاب کنید اگر UI برای نوع موردنظر لازم بداند. ضوابط روزگذشته، روزکاری، هم‌پوشانی و دامنه در سرور نهایی می‌شوند.
۴. «ثبت» را انتخاب کنید. درخواست به فهرست/جزئیات منتقل می‌شود و وضعیت (از جمله `PENDING` یا `ESCALATED`) قابل پیگیری است.
۵. از «درخواست‌ها» برای فیلتر وضعیت/صفحه و «جزئیات» برای وضعیت، تاریخ، روزکاری، یادداشت تصمیم و تاریخچه قابل مشاهده استفاده کنید.

**ساعتی/نیم‌روز:** رابط منطق فرم ساعتی دارد، ولی `GET /policy/client` در backend فعلی `hourlyLeaveEnabled=false` بازمی‌گرداند. همچنین API ایجاد درخواست فیلدهای ساعت را نمی‌پذیرد. بنابراین مرخصی ساعتی/نیم‌روز را قابلیت فعال و قابل استفاده فرض نکنید؛ در صورت نیاز از HR تأیید کتبی و فرایند جایگزین بگیرید.

**پیوست:** صفحه جزئیات برای درخواست قابل مشاهده غیرمحرمانه بخش پیوست دارد. فقط PDF، PNG یا JPEG سازگار تا ۱۰ MiB پذیرفته می‌شود. نوع/امضای محتوای فایل کنترل می‌شود؛ اطلاعات پزشکی را بدون مجوز سازمانی بارگذاری نکنید. پیوست درخواست محرمانه برای غیر HR پنهان/ممنوع است.

**اصلاح و لغو:** درخواست باز را می‌توان لغو کرد؛ لغو برگشت‌ناپذیر معرفی شده است. برای مرخصی تأییدشده، «درخواست لغو» به تصمیم‌گیر می‌رود و همان لحظه حذف/لغو نهایی نیست. «درخواست اصلاح» یک اصلاحیه ایجاد می‌کند؛ فقط یک اصلاح باز مجاز است. ویرایش مستقیم درخواست در صفحه عمومی به‌عنوان گردش‌کار مجاز معمول معرفی نمی‌شود؛ API PATCH فقط مالک/HR مجاز دارد.

## نظرها و اعلان‌ها

- برای درخواست غیرمحرمانه می‌توانید نظر حداکثر ۴۰۰۰ نویسه‌ای اضافه کنید. نظر append-only است و امکان ویرایش/حذف در UI پیدا نشد.
- اعلان‌ها از مرکز اعلان باز می‌شوند و با «خواندم» یا بازکردن پیوند، خوانده‌شده علامت می‌خورند. تنظیمات صدای اعلان و ساکت/روشن در رابط نگهداری محلی هستند؛ ایمیل/PUSH در کد server پیاده‌سازی نشده است.
- متن اعلان اطلاعات دلیل یا جزئیات نوع محرمانه را قرار نمی‌دهد.

## خطاهای معمول

| پیام/کد | اقدام |
|---|---|
| 401 / نشست نامعتبر | ورود دوباره؛ اگر تکرار شد Cookieها را پاک و پشتیبانی را مطلع کنید |
| 403 یا 404 | ممکن است نقش/دامنه دسترسی نداشته باشید؛ 404 می‌تواند برای پنهان‌سازی وجود رکورد باشد |
| 409 | تداخل بازه، وضعیت نامعتبر یا تعارض اصلاح؛ وضعیت درخواست را تازه‌سازی کنید |
| 422 / 400 | تاریخ/روزکاری/توضیح/جانشین را بررسی کنید؛ متن خطا را بخوانید |
| خطای تقویم/سهمیه | تخمین را دوباره اجرا نکنید تا HR تقویم/سهمیه را بررسی کند |
| فایل نامعتبر | پسوند، Content-Type، امضای فایل و سقف ۱۰ MiB را بررسی کنید |

هیچ اطلاعات کارمند دیگری را از راه جست‌وجو یا URL دستکاری‌شده بررسی نکنید. در صورت مشاهده داده غیرمجاز، آن را ذخیره/بازنشر نکنید و فوراً به مالک سامانه گزارش دهید.
